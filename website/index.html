Support automation, built to be trusted

An AI support inbox that never sends anything on its own.

A language model reads each email, sorts it, scores its urgency, flags what needs a person, and writes a draft reply. A human reads every draft before it goes anywhere. Fernbill is a fictional invoicing app, and every email here is synthetic.

What makes it safe to run on real mail

Email is untrusted input

Every message is wrapped in tags, scanned for known injection phrases and judged by the model. Suspected attacks are flagged for a human and get no draft at all.

Drafts are checked

A second pass rejects replies that promise refunds, link outside the help centre, expose other addresses or run long. A failed check becomes a short holding reply.

Risky mail goes to a person

Refunds, legal threats, security reports, lost two-factor devices and angry high-priority customers are always escalated, whatever the model thinks.

Costs and abuse are capped

The public demo allows three requests per visitor per hour and forty per day, behind a hashed visitor id. Secrets never reach the browser.

Visitor text is not kept

Free-text submissions are answered and then forgotten. Only counts and categories are logged, and the dashboard never lists what a visitor typed.

Failures are loud

If any workflow errors, a separate alert workflow emails the owner. A daily digest summarises volume, themes and everything awaiting review.

Under the hood

n8n runs five workflows: the shared triage core, the Gmail trigger, this site's API, the daily digest and the error alerts. gpt-oss-20b does the fast classification and gpt-oss-120b writes the drafts, both served by Groq, and a 54-email evaluation set guards every prompt change. This site is plain HTML and CSS with two small Vercel functions in front of n8n.
